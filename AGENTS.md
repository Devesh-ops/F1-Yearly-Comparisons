## Data constraint

Use only free, public, downloadable data. Check for a working download before committing to a project idea, and record the source URL and retrieval date. Rule out ideas that depend on paid or institution-only sources such as Bloomberg or Compustat.

## Definition of done

- A 2–4 page write-up answers the project question, explains the data and method, quantifies the main finding, and discusses limitations that affect its interpretation.
- A GitHub repository contains the scripts, final outputs, write-up, and a README with data sources and instructions to reproduce the results.
- One résumé bullet describes the completed work and includes at least one verified number that can be traced to a saved output.

## Tools and workflow

Treat Excel and Python as suggested defaults. Use Excel for financial models, sensitivity tables, and workbooks a reviewer can inspect. Use Python for repeatable cleaning, analysis, and visualization. Choose the simplest tool that fits the deliverable. Devesh has used Python and is refreshing it, so favor readable code and briefly explain unfamiliar steps.

Preserve raw inputs. Record data sources, units, and consequential assumptions. Make headline numbers reproducible. Handle routine implementation decisions independently and flag choices that could change the sample or conclusion.

## Writing style

Write for a reader encountering the project for the first time. Use clear, direct English and a professional, conversational tone. Open the report with the question, why it matters, and the main finding. Explain the data and methods in enough detail for a reader to check the analysis. When presenting a result, give its magnitude, units, and a meaningful comparison. Distinguish what the evidence shows from what you infer, and explain any limitation that materially affects the conclusion. Use a chart or table when it makes a result easier to understand.
